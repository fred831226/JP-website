# JP-Website PRD 補充資料

## 決策狀態摘要

- **已鎖定：** 外層 `JP-Website` 為唯一 repository；`/website` 使用乾淨 Next.js App Router + Tailwind，Vercel Root Directory 為 `website`；Content as Code、主導覽與既有 UX 視覺成果保留，V1 不建置後端／CMS／資料庫。
- **刻意延後：** 最新資訊、個別實績詳細頁、GA4、聯絡歸因、cookie consent、RUM、第三方 uptime monitoring，以及 V2 後端／CMS。
- **下游必須承接：** 產品分類映射、最大系列資料量、技術覆核、媒體整理與權利確認。

## 技術與內容營運邊界

### 內容責任與決策理由

客戶目前可由指定網站維護者協助所有網站內容更新；產品更新週期以年為單位，現有 Excel 資料仍不完整。為降低第一版成本、學習與維運負擔，V1 採 static-first Content as Code，不建置後端、CMS、資料庫、登入或管理 API：

- 服務與實績頁的實績摘要、品牌、泵浦類型、用途、系列、型號規格、公司內容、合作夥伴、redirect 與媒體 metadata 使用 Zod 驗證的 JSON；只有內容模型明確指定的長文欄位才使用不可執行的 Markdown。
- Excel 的 `產品系列` 欄位是系列頁分組標準；每個唯一產品系列只有一個正式頁面，所有型號均為該頁規格表資料列。產品名稱、品牌與用途只作為系列內容、顯示欄位或產品總覽篩選條件，不建立獨立公開頁面；泵浦類型頁維持 V1 範圍。
- 所有變更須通過 Git 差異與自動驗證，並由 JP PUMP 核准對應的 source commit；Production 可使用正式環境設定從該 commit 重新建置。
- 初始資料可分批處理；只有通過技術覆核與發布檢查的內容可公開。

此模式消除 V1 後台維運與帳號安全負擔，但非工程人員不能自行即時發布，並會形成維護者單點依賴。必須以統一內容格式、版本控制、更新預覽、發布前檢查、可回復部署及可交接操作文件降低風險；私人關係不能取代正式維護流程。V1 使用小型 typed server-only loaders 讀取 repository 資料，不預建 CMS-neutral ports／adapters；未來真的出現第二資料來源或 runtime write 需求時再做新架構決策。

### 技術狀態

已確認：

- 公開網站前端以乾淨的 **Next.js App Router** 為基礎，位於外層唯一 repository 的 `/website`；既有 Vinext／Vite／Cloudflare／Drizzle starter 與內層 Git boundary 不保留，但核准 mockup 視覺與互動要移植。
- 採 static-first 路線並部署至 **Vercel**；內容在建置時驗證及產生公開頁。
- **Tailwind CSS 4** 是正式 styling utility layer，組合 `DESIGN.md` 的 semantic CSS tokens；原生 HTML 與小型本地元件優先，不預設加入另一套 UI framework、state store 或 headless library。
- V1 不使用後端、CMS、資料庫、ORM、管理員登入、管理 API 或帳號復原 Email。
- 其他前端函式庫、UI 工具、驗證及測試套件由架構依必要性選擇；V1 不加入已延後的分析套件，也不預先承諾第二套前端框架。

V2 延後決定：

- Payload、Managed Headless WordPress、Wix Headless 或其他 CMS 均不屬於 V1 承諾。
- V2 應先驗證非工程人員自助更新、表單、會員或其他伺服器需求，再決定是否需要 CMS、自訂後端與資料庫。
- 產品規格資料可在 V2 繼續由 Git 管理；導入 CMS 不代表必須將所有產品資料搬入資料庫。

### 預覽邊界

主 PRD 不要求同步手機／桌面編輯預覽。V1 以 Git branch／pull request 保存未發布變更，透過 Vercel Preview 檢查完整網站；JP PUMP 核准對應的 source commit 後，Production 可使用正式環境設定從該 commit 重新建置。取消或封存內容以新版本移除，並依網址規則設定 redirect 或正確不存在狀態；重大問題以已驗證 deployment rollback 復原。

## 資訊架構與體驗方向

### 主導覽：不將核心服務藏在「關於我們」

競品導覽截圖：[「關於我們」選單參考](assets/competitor-navigation-about-us.png)

競品將多項企業內容收在「關於我們」選單下。JP-Website 不直接沿用此做法，因為 JP PUMP 的估價、選型、供應、安裝、維修與顧問能力是主要商務價值，不只是企業背景資訊。若將服務藏入「關於我們」，專業買方可能較難發現服務內容與建案證據。

確認採用的主導覽：

1. **產品總覽**
   - 點擊後展開全部正式用途，最多 8 項
   - 清單末尾固定為「全部產品」
   - 用途入口前往已篩選的產品總覽；「全部產品」前往未篩選總覽
2. **服務與實績**
   - 不展開子選單，直接進入「服務與實績」頁
   - 該頁 Hero 呈現服務內容，主體呈現建案實績
3. **關於傑平**
   - 公司資訊
   - 合作夥伴
4. **聯絡我們**

Logo 連回首頁；桌面版可不另設「首頁」選項，手機選單可保留首頁。使用「關於傑平」而非「關於我們」，以提高品牌辨識。桌機與手機的產品及關於選單都採點擊展開，不採 hover；兩種裝置使用相同項目、順序與目的地。

### 全站 Footer

- 每個公開頁 Footer 固定包含三組內容：公司 Logo／識別、`主導覽` 及已核准 `聯絡資訊`。
- 窄螢幕依公司識別、主導覽、聯絡資訊的順序堆疊。
- Footer 不建立第二套資訊架構；未提供或未核准的公司資料、聯絡資料與法律連結直接省略，不顯示佔位內容。

### 首頁 Hero Section

- 所有首頁首屏元素都屬於同一個 Hero Section：底層媒體、上層簡短 SEO 文案、公司介紹、「認識我們」連結，以及品牌／用途快速篩選。
- V1 底層媒體採照片輪播，未來可升級為影片或混合媒體。照片輪播自動播放一次，整段不超過 5 秒，最後停在可單獨作為靜態主視覺的最後一張；不提供手動控制。
- 偏好減少動態、手機省數據或媒體失敗時，直接顯示最後一張靜態主視覺。
- 快速篩選使用兩個單選下拉：品牌與用途皆預設「全部」。任一或兩者維持預設時仍可送出，不顯示必填錯誤；送出後進入帶入相同限制或未限制狀態的產品總覽。
- 寬螢幕的 Hero 文案／篩選面板較前一版縮小約 30%，保留媒體可見範圍；窄螢幕仍使用滿寬堆疊，不壓縮表單控制。
- AI 施工情境圖只作首頁氣氛與情境示意；建案實績及工程成果只使用來源、權利與真實性皆已確認的照片。
- 首頁要優先傳達公司歷史可靠、工程能力強、服務反應真誠快速，且以可驗證內容支撐。

### 首頁 Hero 下方內容

- Hero 下方依序為精簡公司摘要與已核准信任資訊、用途導向產品區、產品／服務與實績／聯絡三個入口、精選已核准建案、已核准合作夥伴及 Footer。首頁不另設獨立聯絡 CTA；聯絡仍由 Header、三入口區與 Footer 到達。
- V1 完全不提供最新資訊模組、列表、內容頁或導覽入口。
- 精選建案或合作夥伴沒有已核准內容時，省略整個選填區段，不以假資料、泛用文案或空卡片補位。
- 用途導向產品區的每張卡片使用核准大圖、用途標題、兩句精簡介紹及右下角半透明箭頭，不顯示 `Learn more`。
- 整張用途卡為單一連結，前往產品總覽並套用品牌「全部」與該用途條件；圖片可在不移動卡片或遮蔽文字的前提下提供克制的 hover／focus 放大回饋。
- 首頁各 feature 可使用低對比技術紋理、漸層與抽象工程背景增加層次。公司摘要採半透明管道與由左至右蜿蜒水流的 3D 感裝飾；所有裝飾均不承載文字、資料或實績證據。
- 產品探索、工程服務、技術聯絡三欄在寬螢幕預設等寬；滑鼠 hover 或鍵盤 focus 時，目標欄平滑變寬、另外兩欄縮小，離開後恢復等寬。觸控與窄螢幕不套用此尺寸變化。

### 服務與實績內容責任

- 網站團隊可依已核准的公司與服務事實撰寫「服務與實績」頁 Hero 的服務內容與 SEO 文案。
- 個別建案的事實、原始文案與照片由 JP PUMP 提供；網站團隊只能修飾與編排，不得改寫事實、擴大成果、虛構案例或補造影像證據。V1 的實績卡／區塊留在單一服務與實績頁，不連向個別實績路由。
- JP PUMP 提供並核准夥伴名單、關係描述、Logo／商標及連結後，由指定網站維護者透過版本控制內容與 Vercel Preview 更新合作夥伴頁。

### 合作夥伴頁布局

- 一個合作夥伴使用一個獨立區塊，區塊整體置中。
- 所有合作夥伴區塊以單欄垂直排列；每增加一個夥伴，就在既有內容下方增加一個相同結構的區塊，不改成多欄卡片網格。
- 寬螢幕版區塊左側放品牌 Logo，右側放 3～4 句品牌與合作範圍介紹。
- 窄螢幕版改為由上而下排列品牌 Logo、介紹與按鈕，整體置中。
- 若已確認該品牌官方網站，介紹區提供標示為「拜訪網站」的外連按鈕；沒有官方網站或網址未確認時不顯示按鈕。

### 產品總覽系列卡片

- 以 UX 工作區的 Flowserve 產品目錄與卡片參考圖作資訊層級參考：卡片頂部為核准產品主圖，下方依序為分類標籤、系列名稱、精簡介紹、關鍵數據摘要與底部提示。
- 每張卡片以一至兩行呈現揚程與揚水量的已覆核範圍摘要，數值須附明確單位；缺漏顯示「未提供」，不得推測。
- V1 不顯示「規格」或「尺寸範圍」操作入口；右下角顯示文字式「看更多」提示。
- 整張卡片為前往該系列唯一詳細頁的單一可操作區域；「看更多」不是巢狀連結或按鈕。滑鼠、觸控與鍵盤使用相同行為，並提供清楚的 hover 與 focus 狀態。
- 卡片使用無外框白色表面與克制陰影；圖片區不使用硬框、實線分隔或過量裝飾性留白。鍵盤焦點仍須清楚可見。
- 響應式網格採寬螢幕兩欄；當兩張卡片無法保留舒適可讀寬度時改為單欄。斷點依內容決定，不以固定裝置名稱硬切。
- 實作保留參考圖的資訊密度與排列原則，但使用 JP PUMP 的品牌視覺、真實產品圖、核准文案與規格資料。

### 系列詳細頁

- 主要閱讀順序固定為：產品大圖 → 關鍵數據表格 → 介紹文案 → 多型號規格表 → 用途標籤 → 頁尾操作區。
- 產品大圖提供點擊放大檢視；滑鼠、觸控與鍵盤皆可啟用。放大層需有清楚的關閉按鈕、支援 `Escape` 關閉、限制焦點於放大層內，並在關閉後將焦點送回原產品圖。
- 關鍵數據表格的固定欄位為揚程最小值、揚程最大值、揚水量最小值與揚水量最大值；揚程單位固定為 `m`，揚水量單位固定為 `L/min`。欄位名稱、數值及單位需清楚對齊，所有數據須經覆核，缺漏不得推測。
- 多型號規格表固定放在介紹文案之後、用途標籤之前，並保留所有已核准型號資料。
- 用途標籤只作為產品適用情境的視覺辨識，不可點擊，也不觸發篩選或頁面導向。
- 頁尾提供前往獨立聯絡頁的單一聯絡入口，不在系列頁直接顯示電話與 Email。
- 中等及寬螢幕將聯絡入口與「返回產品總覽」按鈕置於同一橫向操作區；窄螢幕改為滿寬上下排列，聯絡入口在上、返回按鈕在下。兩個動作需以標示與視覺層級清楚區分，且不得因並排而壓縮文字或點擊範圍。
- V1 不另設性能資料區塊，也不提供 PDF 或其他技術文件下載。

### 獨立聯絡頁

- 頁面採專業深色的一頁式最短聯絡路徑，內容依序為聯絡 Hero 與服務摘要、聯絡資訊、已核准 FAQ，以及條件式地圖；深色處理只用於聯絡頁。
- 電話可直接撥號，Email 可開啟郵件程式，地址為資訊內容；LINE、營業時間、FAQ 與地圖只有在正式資料及發布方式已核准時才顯示。
- V1 不放聯絡表單；缺少或未核准的欄位與整個選填區段直接省略，不顯示空白區塊或假資料。
- 聯絡頁不顯示返回產品總覽、返回系列頁或其他來源脈絡；V1 不在網址、瀏覽器儲存或事件中保留來源歸因。
- 窄螢幕依聯絡 Hero、服務摘要、聯絡資訊、FAQ、條件式地圖及 Footer 的順序堆疊；所有聯絡動作保留足夠觸控範圍。

### UX 與視覺方向

- 整體感受：完整、專業、現代、技術可信、不花俏。
- 專案起始時沒有既定品牌色或指定字體；使用者授權 UX 依公司金色招牌照片與白底藍字 Logo 照片建立完整色彩、字體與元件系統。正式結果記錄於 final UX 規範 `DESIGN.md` 與 `EXPERIENCE.md`。
