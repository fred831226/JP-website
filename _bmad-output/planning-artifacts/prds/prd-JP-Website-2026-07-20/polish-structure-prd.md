# JP-Website PRD 結構審查

## Document Summary

- **Purpose:** 供決策者確認產品範圍，並作為 UX、架構與故事拆解的來源文件。
- **Audience:** JP PUMP、產品負責人、UX、架構、開發與驗收人員。
- **Reader type:** humans；適用 Human-Reader Principles，保留有助理解與掃讀的摘要、具名旅程、表格、分組標題、範例與留白。
- **Structure model:** Strategic/Context（Pyramid）；第 5、7 章另以 Reference/Database 的一致格式承載 FR 與 NFR。
- **Current length:** 約 10,108 個中英文字單位、13,180 個非空白字元，共 11 個主要章節。中文以單一漢字、英文與數字以連續詞組計數，因此這是結構比較用的穩定估算，不是自然語言斷詞結果。
- **Core question:** JP-Website V1 為誰解決什麼問題、承諾哪些成果與能力、排除哪些範圍，以及上線前有哪些品質門檻、依賴與未決事項？
- **This document exists to help:** JP PUMP 與交付團隊確認 V1 的共同決策邊界，並讓 UX、架構、開發及驗收人員能可靠擷取需求。
- **Style guide:** 未提供；本次依此結構審查技能的 Human-Reader Principles 與 Pyramid 模型評估。
- **Length target:** 未指定。

### Pyramid Model Assessment

- **Conclusion/status first:** 部分符合。願景與問題在前，但沒有一頁式「決策摘要／V1 範圍／上線阻塞項」，決策者必須讀到第 8–10 章才能確認完整狀態。
- **Logical grouping:** 大致符合。功能、NFR、風險與未決事項各自分群清楚。
- **Critical-first ordering:** 部分符合。成功指標在前是優點；使用者旅程在其引用之後、MVP 與發布阻塞項在後段，降低首次閱讀效率。
- **MECE:** 部分符合。第 2.2 與第 8.2、 第 3.4 與第 7 章、 第 3.6 與 FR-34～FR-36 存在不同程度重疊。
- **Evidence supports argument:** 符合。差異化、技術覆核、案例與權利治理都有相應 FR/NFR 或依賴。

### Human-Reader Flow Assessment

- **Reader journey:** 願景 → 目標 → 指標的開頭順序合理；但接著進入名詞與 36 項 FR，讀者直到之後才看到具名旅程，形成「先看規格、後看使用情境」的逆向理解。
- **Premature detail:** FR-25 的 Excel G 欄映射，以及未決事項中的 Next.js 整合評估，屬資料移轉／技術決策層級，早於架構與移轉規格所需。
- **Missing scaffolding:** `管理者` 已定義，但反覆出現的「指定網站維護者」未在名詞表定義；此外 `UJ-*` 在第 5 章先引用、第 6 章才解釋。
- **Anti-patterns:** 沒有 FAQ 或無用途附錄；主要反模式是範圍與品質門檻的重複來源。
- **Pacing and visual variety:** 標題、表格、條列與具名旅程提供足夠留白與掃讀節奏。第 5 章較長但有六個清楚功能群，不建議為縮短而移除 FR 驗收結構。
- **Comprehension aids:** 具名旅程、風險／依賴表、穩定 FR/NFR 編號及「可驗收結果」都直接提升理解與下游擷取，應保留。

## Recommendations

### 1. MOVE/MERGE - 在文件最前建立「決策摘要」，並把 V1 範圍與發布阻塞項前置

**Rationale:** 決策者目前要讀到第 8–10 章才看完整範圍、阻塞依賴與未決事項，違反 Pyramid 的 critical-first 原則；可把既有內容移入一頁式摘要，包含產品決策、V1 in/out、主要成功指標、發布阻塞項與尚待決策事項，再由後文提供細節。

**Impact:** 淨減約 120 個中英文字單位；以搬移與引用為主，不新增新內容。

**Comprehension note:** 這項調整會降低決策者首次閱讀成本，且不犧牲 UX／架構需要的詳細內容。

### 2. MOVE - 將第 6 章「目標使用者與使用者旅程」移到功能章之前

**Rationale:** 第 5 章在讀者尚未認識 UJ-1～UJ-5 前即大量引用它們；先建立角色、任務與真實順序，再閱讀 FR，較符合人類由情境到規格的理解路徑。

**Impact:** 約 0 個中英文字單位；純重排。

**Comprehension note:** 具名旅程是有效的理解與參與輔助，不應因壓縮而刪除。

### 3. MERGE - 合併第 2.2「V1 明確非目標」與第 8 章「MVP 範圍」

**Rationale:** 第 8 章的範圍內／外幾乎是第 2、5、7 章的摘要重述；應保留一個靠前的 V1 範圍來源，並由 FR/NFR 作為詳細定義，避免兩處清單日後漂移。

**Impact:** 約減少 260 個中英文字單位。

**Comprehension note:** 應保留一份完整且易掃讀的 in/out 清單；刪除的是重複來源，不是決策摘要本身。

### 4. MERGE - 將第 3.4「發布與持續品質門檻」改為引用第 7 章的 NFR

**Rationale:** Core Web Vitals、WCAG、資料覆核與素材權利已在 NFR-1、NFR-3、NFR-11 及相關 FR 中定義，重複寫出完整門檻增加日後不一致風險。

**Impact:** 約減少 90 個中英文字單位。

**Comprehension note:** 成功章仍應保留「發布門檻」小節，但以 NFR ID 與通過／不通過原則摘要，不再複製數值。

### 5. CONDENSE - 壓縮第 5 章各功能群的描述與 FR 之間的重述

**Rationale:** 多個功能群前言已先列出能力、邊界與政策，隨後 FR 又逐項重述；每群保留一段「目的＋邊界」及 `實現旅程` 即可，具體行為與驗收只留在 FR。

**Impact:** 約減少 360 個中英文字單位。

**Comprehension note:** 不應刪除穩定 FR 編號、可驗收結果、例子或 `實現旅程`；這些是人類理解與故事擷取的核心結構。

### 6. MOVE - 將資料來源欄位與技術候選條件移到 addendum／移轉規格

**Rationale:** FR-25 的 Excel「G 欄」映射與未決事項中的 Next.js 整合條件是實作／移轉細節，放在主 PRD 會讓產品能力與當前檔案格式耦合；主文應保留「權威來源、不可誤用舊用途欄、需可驗證」的結果。

**Impact:** 約減少 35 個中英文字單位。

**Comprehension note:** 移出而非刪除；架構與資料整理仍需能從 addendum 或移轉規格追溯這些決策。

### 7. QUESTION - 是否補齊「指定網站維護者」的名詞定義

**Rationale:** 此角色在目標、FR、旅程、風險與未決事項中承擔關鍵責任，但名詞表只定義 `管理者`，可能使權限與營運責任被混淆。

**Impact:** 增加約 25 個中英文字單位。

**Comprehension note:** 對 JP PUMP、架構與驗收讀者都有直接幫助，建議接受。

### 8. PRESERVE - 保留具名旅程、FR/NFR 全域編號、逐項驗收結果與風險表

**Rationale:** 這些元素雖使文件較長，卻同時支援人類理解、跨角色討論、UX／架構來源擷取與後續故事拆解，是有功能的內容而非冗詞。

**Impact:** 約 0 個中英文字單位；明確避免誤刪約 5,500 個高價值文字單位。

**Comprehension note:** 若移除這些結構，會明顯降低可驗收性與下游擷取品質。

## Summary

- **Total recommendations:** 8
- **Estimated reduction:** 約 840 個中英文字單位，約為原文 8.3%；若連同前置摘要的編排微調，合理範圍為 800–950 個文字單位。
- **Meets length target:** No target specified
- **Comprehension trade-offs:** 建議只移除重複來源與過早的實作細節；具名旅程、驗收結果、編號與表格均保留，因此預期不犧牲理解或參與感。若進一步追求超過約 10% 的壓縮，最可能傷害的是 FR/NFR 可驗收性與下游故事擷取，不建議。
